Frontend Documentation

Financial Market Analytics Platform

The frontend is the interactive presentation layer of the Financial Market Analytics Platform.

It provides a professional web-based dashboard for exploring historical market data, viewing technical signals, and displaying machine learning predictions generated by the backend analytics platform.

The frontend is implemented using Next.js, React, TypeScript, Tailwind CSS, and Lightweight Charts.

The dashboard communicates with the FastAPI backend through HTTP requests and presents market information in a unified analytics environment.


Frontend Responsibilities

The frontend is responsible for:

* Providing the main financial analytics dashboard.
* Allowing users to select supported financial instruments.
* Retrieving historical OHLC market data from the backend.
* Displaying historical price action using candlestick charts.
* Displaying the latest market price.
* Calculating and displaying the daily price change.
* Presenting a rule-based technical signal.
* Presenting machine learning prediction results.
* Displaying model confidence information.
* Comparing technical and machine learning signals.
* Monitoring backend API availability.
* Handling loading states.
* Handling unavailable market data.
* Providing a responsive user interface for desktop and smaller screens.

The frontend does not perform model training.

Machine learning training, feature engineering, prediction generation, and model management are handled by the backend.

Market Data Loading

Historical market data is retrieved from:

/analytics/ohlc/{symbol}

For example:

/analytics/ohlc/AAPL

The dashboard requests this endpoint whenever the selected market changes.

The request uses:

cache: "no-store"

This prevents the browser from relying on cached market-data responses during dashboard interaction.


OHLC Data

The dashboard expects OHLC information containing:

* Date.
* Open.
* High.
* Low.
* Close.

The frontend converts incoming values to numeric values before displaying them.

The date is normalized to the calendar date:

YYYY-MM-DD

Invalid numerical values are removed from the chart dataset.

This provides an additional frontend data-quality check before the information reaches the chart component.


Latest Price

The dashboard extracts the most recent record from the market-data response.

The latest closing price is displayed as:

Current Price

The value is formatted to two decimal places.

For example:

$303.42

If valid market data is unavailable, the dashboard displays:

—

instead of attempting to display an invalid value.


Daily Price Change

The dashboard calculates the percentage change between:

* Latest close.
* Previous close.

The calculation is:

((latest price - previous close) / previous close) × 100

The resulting value is displayed as the daily change.

Positive changes are presented using the positive signal styling.

Negative changes are presented using the negative signal styling.


Technical Signal

The dashboard provides a rule-based technical signal using:

* MA7
* MA20

The backend OHLC response includes these moving-average values.

The frontend compares the most recent MA7 and MA20 values.

The rule is:

MA7 > MA20
    -> BUY
MA7 < MA20
    -> SELL
MA7 = MA20
    -> HOLD

If either moving-average value is unavailable, the dashboard defaults to:

HOLD

This technical signal is independent from the machine learning prediction.


Technical Signal Presentation

The technical signal is displayed in the Market Overview section.

The dashboard identifies it as:

Technical Signal

The interface also displays:

MA7 / MA20

The description explains that the signal is derived from moving-average positioning.

Signal styling changes according to the result:

BUY  -> positive styling
SELL -> negative styling
HOLD -> neutral styling

This makes the technical interpretation immediately visible.

Candlestick Data Validation

Before chart rendering, the CandleChart component performs additional data cleaning.

It:

1. Normalizes dates.
2. Validates the date format.
3. Converts OHLC values to numbers.
4. Removes invalid numerical values.
5. Removes duplicate dates.
6. Sorts observations chronologically.

The expected date format is:

YYYY-MM-DD

Duplicate dates are removed using a JavaScript Set.

The resulting dataset is sorted chronologically before being passed to the candlestick series.

Responsive Chart Behavior

The CandleChart component uses:

ResizeObserver

to monitor the chart container.

When the container width changes, the chart width is updated.

This allows the visualization to adapt to different screen sizes and dashboard layouts.

The chart is therefore designed to work across:

* Desktop screens.
* Laptop screens.
* Narrower browser windows.
* Responsive dashboard layouts.


Chart Lifecycle Management

The chart is created inside a React useEffect.

When the component is removed or its data changes, the existing chart is cleaned up.

The cleanup process:

1. Disconnects the ResizeObserver.
2. Removes the Lightweight Charts instance.

This prevents unused chart instances and observers from remaining in memory.

Error Handling

The dashboard handles backend failures without crashing the interface.

For market-data failures, it displays:

along with a descriptive message.

If the backend cannot be reached, the frontend reports that it is unable to connect to the backend.

The chart data is cleared when market data cannot be loaded.

The dashboard also resets the displayed technical signal to:

when appropriate.


ML Prediction Error Handling

If the prediction endpoint does not return a successful response, the dashboard does not display a fabricated prediction.

Instead:

prediction = null

The ML section displays:

N/A

when no prediction is available.

This prevents unavailable model output from being represented as a valid prediction.

Separation of Responsibilities

A major architectural principle is the separation between presentation and analytics.

The frontend does not:

* Train machine learning models.
* Access PostgreSQL directly.
* Perform ETL.
* Manage model files.
* Perform feature engineering for prediction.
* Maintain the model registry.

Instead, these responsibilities remain on the backend.

The frontend consumes backend APIs and presents their results.

This separation improves maintainability and makes the platform easier to evolve.


Data Flow

A typical dashboard request follows this sequence:

1. User selects a symbol.
2. React updates the selected symbol.
3. The dashboard requests:
   /analytics/ohlc/{symbol}
4. Backend retrieves historical market information.
5. Frontend validates and transforms the OHLC data.
6. CandleChart renders the historical price action.
7. Frontend identifies the latest and previous closing prices.
8. Frontend calculates the daily price change.
9. Frontend compares MA7 and MA20.
10. Frontend displays the technical signal.
11. Frontend requests:
    /predict/{symbol}
12. Backend returns the machine learning prediction.
13. Frontend displays:
    - Signal
    - Probability
    - Confidence
    - Confidence level
    - Model information
    - Performance metrics when available
14. Dashboard compares the technical and ML signals.


Frontend Data Validation

The frontend performs defensive validation before rendering financial data.

Examples include:

* Checking whether API responses are successful.
* Checking whether market data is available.
* Converting values to numbers.
* Rejecting non-finite OHLC values.
* Validating date formats.
* Removing duplicate dates.
* Sorting chart observations.
* Handling missing prediction results.

These checks reduce the likelihood that malformed API data will break the user interface.

The application is built with:

Next.js
React
TypeScript
Tailwind CSS
Lightweight Charts
Recharts

The main dashboard allows users to select supported financial instruments and examine historical market behavior through interactive candlestick charts.
