Frontend Documentation

Financial Market Analytics Platform

The frontend is the interactive presentation layer of the Financial Market Analytics Platform.

It provides a professional web-based dashboard for exploring historical financial market data, viewing technical indicators, comparing technical and machine-learning signals, and displaying machine-learning predictions generated by the backend analytics platform.

The frontend is implemented using Next.js, React, TypeScript, Tailwind CSS, Lightweight Charts, and Recharts.

The application communicates with the FastAPI backend through HTTP API endpoints and presents backend-generated financial information through a responsive financial analytics dashboard.

The frontend does not directly access PostgreSQL or machine-learning model files. Instead, it consumes structured API responses provided by the backend.

15. Market Data Loading

Historical market data is retrieved from:

/analytics/ohlc/{symbol}

For example:

/analytics/ohlc/AAPL

The frontend expects structured historical OHLC information from the backend.

18. Daily Price Change

The dashboard calculates the percentage change between:

* Latest close.
* Previous close.

The calculation is:

((latest price - previous close) / previous close) × 100

The resulting value is displayed as the daily price change.

Positive changes use positive signal styling.

Negative changes use negative signal styling.

This provides users with an immediate view of the most recent price movement.

⸻

19. Technical Signal

The dashboard provides a rule-based technical signal using:

* MA7.
* MA20.

The backend OHLC response includes these moving-average values.

The frontend compares the most recent MA7 and MA20 values.

The rule is:

MA7 > MA20
    -> BUY
MA7 < MA20
    -> SELL
MA7 = MA20
    -> HOLD

If either moving-average value is unavailable, the dashboard defaults to:

HOLD

The technical signal is independent from the machine-learning prediction.

29. Candlestick Data Validation

Before chart rendering, the CandleChart component performs additional data cleaning.

It:

1. Normalizes dates.
2. Validates the date format.
3. Converts OHLC values to numbers.
4. Removes invalid numerical values.
5. Removes duplicate dates.
6. Sorts observations chronologically.

The expected date format is:

YYYY-MM-DD

Duplicate dates are removed using a JavaScript Set.

The resulting dataset is sorted chronologically before being passed to the candlestick series.

This protects the visualization layer from malformed or duplicated market records.

33. Chart Lifecycle Management

The chart is created inside a React useEffect.

When the component is removed or its data changes, the existing chart is cleaned up.

The cleanup process:

1. Disconnects the ResizeObserver.
2. Removes the Lightweight Charts instance.

This prevents unused chart instances and observers from remaining in memory.

Proper lifecycle management helps reduce the possibility of memory leaks and duplicated chart instances during dashboard updates.

51. Frontend and Backend Contract

The frontend depends on stable API response structures.

The backend therefore acts as the contract between the frontend and underlying data and machine-learning systems.

The frontend expects structured JSON responses rather than database-specific objects.

This means the frontend remains independent of:

* PostgreSQL schema details.
* SQLAlchemy implementation.
* Machine-learning model file format.
* Training implementation.
* ETL implementation.

This abstraction allows individual backend components to evolve without requiring major frontend changes.

52. Dashboard Performance

Dashboard performance is important because financial charts can contain a large number of data points.

The application avoids unnecessary computation in the browser where possible.

Performance considerations include:

* Limiting unnecessary API requests.
* Avoiding repeated expensive calculations.
* Separating visualization data from ML processing.
* Reusing React components.
* Keeping chart updates efficient.
* Avoiding unnecessary state changes.
* Keeping visualization-specific backend endpoints lightweight.

A major architectural optimization was made to the backend analytics endpoint.

The dashboard does not need to execute the complete machine-learning feature-engineering pipeline merely to display historical OHLC information and moving averages.

The analytics endpoint therefore provides visualization-specific data without unnecessarily invoking the full ML pipeline.

This reduces unnecessary backend computation and improves dashboard responsiveness.
